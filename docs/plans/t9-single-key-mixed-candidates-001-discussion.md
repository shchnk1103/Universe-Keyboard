# 讨论稿：单键九宫格为什么要像苹果一样「一按就有很多词」

> **对应产品记录：** [`PD-T9-SINGLE-KEY-MIXED-CANDIDATES-001`](../product-decisions/T9-SINGLE-KEY-MIXED-CANDIDATES-001-authorization.md)（Proposed）  
> **对应任务单：** [`T9-SINGLE-KEY-MIXED-CANDIDATES-001`](../assignments/t9-single-key-mixed-candidates-001.md)（Assignment Pending）  
> **和今天修的 bug 的关系：** **不是一类事**（见下文）

## 1. 用大白话说清楚两件事

### 今天已经修好的（别和下面混在一起）

| 现象 | 原因（人话） | 修了什么 |
|---|---|---|
| 点候选词，输入框里出现**两遍** | 系统把「上屏」做了两次 | 保证只上屏一次 |
| 候选划到后面**加不出更多**（长拼音时大约卡在一页） | 后台读「更多候选」读错地方 | 改成去真正的引擎里继续读 |

这些是 **dual-gate 异步路径写错/读错**，属于 **正确性 bug**。

### 你想做成的目标（新产品方向）

苹果系统九键：只按一下 **MNO**，候选栏里会同时出现  
**吗 / 你 / 哦 / 年 / 能 / 美 / 那…**  
也就是 **m、n、o 相关的字词混在一起**。

我们现在（雾凇 / RIME 九键）：只按一下 MNO（引擎收到数字 `6`），  
中文候选往往只有 **很少几个**（历史上大约 **4 个**，还偏 o 音，比如哦、噢一类）。  
上面的 **m / n / o** 是「选拼音」用的路径条，**不会自动把三套中文词并到候选栏**。

这是 **产品体验目标**，不是「分页没写好」的小修。

---

## 2. 为什么用户会觉得我们「不对」

用户心里的模型是：

> **一个键上写了 MNO → 按一下就应该能选到 m、n、o 开头的常用字。**

苹果按这个模型做。  
RIME 九键按另一个模型做：

> **按键变成数字码 `6` → 在词典里查「码是 6」的结果。**  
> 查到的集合很小，不等于「m 的全部 + n 的全部 + o 的全部」。

所以：

- 路径条显示 m/n/o → **我们做得对**（方便你精确选拼音）  
- 候选很少、偏 o → **对 RIME 来说常见**，对 **苹果用户直觉来说偏弱**

两边没有谁「算错加法」，是 **目标不一样**。

---

## 3. 我们想立的目标（一句话）

**单按一个九键数字（至少先从 MNO/`6` 谈起），候选栏里就应出现该键字母组混在一起的中文候选，尽量接近苹果首键的感觉；不必先点路径条上的 m 才能「发现」中文词。**

先不做、也不承诺：

- 和苹果一模一样的智能联想、整句、emoji 排序  
- 长串输入全面重做成苹果  
- 对外宣传性能数字  

---

## 4. 可选做法（讨论用，都还没批准开工）

用尽量直白的说法：

| 方案 | 做什么 | 好处 | 代价 / 风险 |
|---|---|---|---|
| **A. 按一下键，后台分别查 m、n、o 再拼起来** | 引擎里短暂试 `m`/`n`/`o`，合并候选后显示，再回到数字 `6` | 最接近苹果「一按就有很多词」 | 多几次引擎查询，可能变慢；要小心别把输入状态弄乱；和 dual-gate 排队要设计好 |
| **B. 改词库 / 方案，让数字 `6` 本身就出更多词** | 从 RIME 配置侧加码 | 运行时逻辑简单 | 和上游雾凇难同步；部署、词库责任变重 |
| **C. 折中：现在太少才补查** | 若首屏少于某个数量，再补 m/n/o | 平时省一点力 | 规则复杂（什么叫「太少」、怎么排序） |
| **D. 不改候选，只引导先选拼音** | 保持现状，文案/引导 | 最省事 | **达不到**你说的苹果直觉 |

**推荐讨论顺序：** 先决定要不要坚持「接近苹果首键」→ 再在 A/B/C 里选，**D 等于放弃这个目标**。

---

## 5. 和现有规则会打架的地方（需要提前知道）

以前定过（ADR 0021 一类）：

- 路径条的 m/n/o 是 **选拼音用的**  
- **不要**用路径规则去「生成一整套中文候选引擎」

若做方案 A/C，等于说：  
**在「只有一个数字、还没选定拼音」时，允许有限地多查几次字母，专门服务首屏中文候选。**

这需要：

1. **产品拍板** 采用哪条方案  
2. **架构改一纸规则**（改 ADR 或新 ADR）  
3. 再开正式任务、写测试、真机对比  

在此之前 **不应写进正式产品代码**。

---

## 6. 建议的验收样子（以后真做时再锁死）

人话验收（合成输入即可）：

1. 只按一次 **MNO**  
2. 候选栏里能看到 **至少来自 m、n、o 不止一类** 的常用字（不必和苹果逐字相同）  
3. 点其中某个字 → **只上屏一次**、拼音状态干净  
4. 长按/多键输入时，不能明显卡死或乱序（和 dual-gate 要兼容）  
5. 可选：和苹果并排截图，只比「首键丰富度」，不比整句智商  

数字门槛（比如「至少 12 个」「必须含吗/你/那」）留给产品 Gate 再定，本稿不写死。

---

## 7. 建议你拍板的三道题

1. **目标确认：** 是否正式接受「单键混合中文候选、接近苹果首键」？  
2. **方案倾向：** 更想 A（查三次拼起来）、B（改词库方案）、还是 C（少了再补）？  
3. **范围：** 先做 **只有 6（MNO）**，还是一上来 **2–9 全部九键**？

拍板后，再开正式 Assignment 的 Ready，进入设计 / Spike，而不是直接改键盘热路径。
