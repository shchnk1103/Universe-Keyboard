# ADR 0037: Keyboard Height Host Budget Trust

## Status

Proposed

2026-10-26 Asia/Shanghai；BUILD167-FIX-S3-HEIGHT-001 修订 R1 / R2。候选实现等待独立 Architecture / Quality 复审；
不是产品合同变更、Product Gate、合并或 Release 授权。

## Context

S2 真机四量读数表明：自定义行高或 Path 0→34 发出增高请求后，宿主仍暂时保留旧 bounds，
约32–50ms后才增高。旧代码立即把低 bounds 记为 accepted，于是显示行高被夹低；
Path 的固定项增至108时甚至不足四行40，导致根 alpha=0、停用高度约束，出现输入不可命中的窗口。

R0 使用两个相同布局读数，第二次却由自己的主队列 setNeedsLayout 制造，评审探针约10ms内即可隐藏，
不能证明宿主已稳定。手工同步布局测试绕开了主队列，未检出该机制。
S2 来源是外置 reports/executor-report.md，SHA-256
`3961240f6cbdb959a6cff554ca4d0ef567d486659252e28365f3df33f7cc6672`；
Architecture R1 报告 SHA-256 `e8519bd6a740f378761874a509467b55c8570ff00e2464a3d43ff2e11ee43c94`。
这些是单机与模拟器证据，不是所有系统/宿主的时延上界。

## Decision

### 1. 用显示帧时间，不用自制布局次数

新请求代际（目标高度、整屏方向几何、新一次出现）清除旧预算。可见窗口布局首次发现实际高度不足时，
启动单个 CADisplayLink，使用与 CACurrentMediaTime 同域的单调帧 timestamp。布局回调只负责启动/检查满足请求，
无论来源是宿主还是扩展，都不能仅凭调用次数证明低预算稳定；不再安排额外 setNeedsLayout 取样。
观察不涉及输入、候选文字、RIME或同步磁盘 I/O。

实际高度达到请求可以立即采用。低预算同时满足以下条件才采用：

- 已观察至少4/60秒，约66.7ms；
- 已执行至少两次真实帧采样；
- 相邻读数保持相同至少1/60秒，约16.7ms；变化时重新累计稳定间隔。

66.7ms选自 S2 的最大约50ms再加一个60Hz帧余量；16.7ms要求稳定读数横跨一个名义60Hz帧。
这是短、有依据、可测试的信任窗口，不是等待固定长延时后无条件接受。60/120/更高刷新率都按实际时间，
120Hz时至少约8帧才达到观察门槛；不能把四个120Hz帧误当66.7ms。frame source与单调时钟可注入测试。

### 2. 待结算保持意图，稳定低预算仍遵守下限

新请求或新的低预算观察期间清除旧 accepted，保持按方向封顶的意图行高与可见性。
选择这一策略是为了避免过渡期制造按键不可命中的隐藏窗口，也避免显示夹低反馈进滑块/保存路径。
低预算经判定稳定后，按 floor((accepted−固定项)/4) 夹低；不足40仍执行原隐藏规则，不突破下限。
低预算恢复后可以重新显示。候选、Path固定项、默认45/254/288、横屏45、竖屏50%、旋转750/999不变。

调节上限和保存延续 R0 已获认可的部分：滑块上限只来自方向封顶；确定保存40至当前方向上限内的意图整数，
显示夹低不写回，重置删除。这遵循[UI-4合同](../../product-decisions/UI4-KEYBOARD-HEIGHT-001-product-contract.md)第53/58行。

### 3. 后续低读数同样需要证明

结算后，只要宿主出现与已接受预算不同的新低读数，就重启同一时间判据，不能直接采用动画中间值。
达到请求立即清预算/结束观察；相同的已接受预算不重新观察，避免自身约束引起重复协商。

### 4. 硬上限与清理

每次观察最多32次帧采样，或在帧 timestamp 达到8/60秒（约133.3ms）仍未证明稳定时停止。
两倍观察窗口给迟到/振荡读数有限的稳定机会；32次覆盖240Hz下约133ms，另防不前进的异常时钟无限采样。
没有合格稳定读数就保留意图、accepted=nil；同一观察标为 exhausted，并记录耗尽时的 bounds；重复相同低读数不能自动重试。
后续布局读到不同 bounds 时才解除 exhausted，开始一个受相同时间/样本上限约束的新窗口；
变化本身不是稳定证据，仍需完整信任判据。宿主持续变化可驱动多个有界窗口，但没有帧/布局自调度重试，
窗口数量受外部变化次数与每窗口时长约束；停止变化后可以收敛至稳定低预算。
达到请求、新目标、几何或出现变化也可清除耗尽状态。

显示帧暂停时不轮询，时间截止在下一帧检查，因此不是后台墙钟定时承诺。该策略不会自行触发任何额外布局；
结算只更新一次显示约束，振荡不能产生无限布局队列。窗口移除、宿主挂起或代际变化立即取消帧观察；
观察身份验证拒绝已取消/旧代际回调，显示链路 target 弱持有观察者。

## Alternatives Considered

- R0 自调度两次相同 bounds：否决。第二读数可在约10ms内自制，远早于S2的宿主增高，不能作为宿主稳定证据。
- 只靠“宿主触发”的布局计数：不采用。当前 UIInputViewController 回调没有可靠来源标记，不能区分扩展与宿主触发。
- 固定较长 asyncAfter 后立即接受：不采用。无论读数是否仍变动都采用，且会拖延真实低预算处理；本方案每帧检查满足请求/稳定条件并有短上限。
- 只数固定4帧：不采用。120Hz四帧仅约33ms，不能覆盖S2约50ms。
- 永久忽略宿主预算：不采用。违反稳定低预算时跟随宿主/下限的既有规则。

## Consequences

过渡期间不因旧低预算夹低或隐藏，调节保存仍与显示预算分离。拒绝增高的稳定宿主约67ms后可收敛，
观察期间仅内存读数与显示帧回调，不进入按键热路径。代价是短暂维持可能超出旧容器的意图几何。

## Risks

S2单机时延不是平台保证；超过约66.7ms才开始增高的宿主仍可能在此前被判为低预算，须真机复测。
振荡耗尽时保持意图可能超出实际容器；该不确定性不伪装为已接受预算，也不以隐藏掩盖。
耗尽后自愈依赖后续布局读到变化；如果最终稳定值恰好等于耗尽读数且没有中间变化布局，仍不会重启。
N2：本方案只在可见布局回调读到不足高度时启动采样；请求变化后如果宿主不再产生布局回调，观察不会启动。
此轮选择保留该入口，避免扩大请求/布局重入路径；阶段 B 必须真机确认“拼音栏出现时是否必有布局回调”。
N3：结算后遇到不同低读数会撤销旧 accepted，在约66.7ms（实际帧到达及稳定条件可能延长）的观察期间
按意图高度显示，而非保留旧钳制。这是有意避免把旧宿主预算沿用到新协商的代价，可能短暂闪现意图高度。
时间/帧判据依赖显示帧到达，后台不承诺定时收敛。模拟器测试不证明所有键位、跨重排持键或真实输入成功。

## Follow-up Work

独立 Architecture / Quality 复审本判据、上限、生命周期与回归证据；Human另授后真机检查调高保存、Path出现、快速连按漏按与错行。
D4“命中下一行”根因不在本修订，R174关闭；不凭模拟器通过批准设备、push、PR、merge或Release。
F1回归须在R0失败而R1通过；另用可控时钟/帧源覆盖30/40/50ms迟到、稳定拒绝、低于40、结算后读数与振荡上限。
